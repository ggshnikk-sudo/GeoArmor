# GeoArmor

Движок 3D-брони для Minecraft **26.2** (Fabric), которым управляет ресурспак. Пак пишет, какой
GeckoLib-модели, текстуре и анимации соответствует предмет брони — мод подменяет ванильный слой
и рисует эту модель на надетой вещи. Работает с любым предметом, который игра считает бронёй:
ванильным, серверным, модовым.

Один обычный `json`-файл в паке — и железный шлем превращается во что угодно. Одна и та же модель
может нести весь сет: каждая часть берёт из неё свои кости.

**Требования:** Minecraft 26.2, Fabric Loader 0.19+, [GeckoLib](https://modrinth.com/mod/geckolib)
5.5.5+, Fabric API, Java 25. Мод **клиентский**: на сервере он не нужен, предметы должны лишь
совпадать у всех (ванильные совпадают всегда).

## Установка

1. Поставь Fabric Loader для 26.2.
2. Положи в `mods/` три файла: `geoarmor-1.0.0.jar`, GeckoLib, Fabric API.
3. Положи пак с бронёй в `resourcepacks/` и включи его в игре.

Мод ничего не делает без пака — без него броня рисуется ванильно, как обычно.

## Быстрый старт

Минимальный пак — три файла: описание, геометрия и настройка брони.

```
mypack/
├── pack.mcmeta
└── assets/
    └── mypack/
        ├── config/armor/armor.json
        ├── geckolib/models/iron_set.geo.json
        └── textures/armor/iron_set.png
```

`pack.mcmeta`:

```json
{
  "pack": {
    "description": "Моя броня",
    "min_format": 88,
    "max_format": 88
  }
}
```

`assets/mypack/config/armor/armor.json`:

```json
{
  "armor": {
    "minecraft:iron_helmet": {
      "geo": "mypack:iron_set"
    }
  }
}
```

Всё. Текстуру мод найдёт сам — `assets/mypack/textures/armor/iron_set.png` (имя берётся от геометрии).
Дальше достаточно дописать остальные части сета (`iron_chestplate`, `iron_leggings`, `iron_boots`)
с тем же `geo`.

Готовый пример со всеми ключами — в `examples/geoarmor-sample/` (там железо и алмаз
натянуты на одну модель). Самый маленький рабочий пример — в `examples/geoarmor-template/`:
один куб-шлем, одна кость `armorHead`, одна текстура с маской свечения и один файл настроек. Это
шаблон, с которого удобно начинать: скопируй папку, поменяй неймспейс и `geo`.

## Формат пака

Настройки лежат в `assets/<неймспейс>/config/armor/*.json`. Читаются все неймспейсы, все паки
сразу; файлы глубже одного уровня не читаются. Если один и тот же предмет объявлен в двух файлах,
мод берёт файл, который позже по алфавиту, и пишет об этом предупреждение в лог.

Ключи внутри файла — **id предмета**, а не слот:

```json
{
  "armor": {
    "minecraft:iron_chestplate": {
      "geo": "mypack:diamond_set",
      "texture": "mypack:textures/armor/diamond_set.png",
      "animation": "mypack:diamond_set",
      "idle": "misc.idle",
      "display": {"translate": [1.6, -2.75, 0], "rotate": [0, 0, 0], "scale": 1.6},
      "translucent": false,
      "glow": "radiant"
    }
  }
}
```

| Ключ | Обязательный | Что делает |
|---|---|---|
| `geo` | да | Геометрия (Bedrock/GeckoLib). Без него запись отбрасывается |
| `texture` | нет | Полный путь `textures/.../name.png`. По умолчанию — рядом с геометрией: `mypack:diamond_set` → `mypack:textures/armor/diamond_set.png` |
| `animation` | нет | Файл анимаций. Без него вещь статична |
| `idle` | нет | Какой клип проигрывать в покое (по умолчанию `misc.idle`) |
| `display` | нет | Смещение/поворот/масштаб модели на вещи (см. ниже) |
| `translucent` | нет | Смешивать альфу текстуры вместо жёсткого вырезания (по умолчанию `false`) |
| `glow` | нет | Свечение: `true`/`false`, `"glow"`/`"radiant"` или `{"mask": "..."}` (см. ниже) |

Незнакомые ключи мод игнорирует — пак, написанный для другого движка брони, свою геометрию здесь
прочитает; лишнее просто не сработает.

**Запись нужна на каждую часть.** Шлем и нагрудник — разные предметы, одной записи на сет не
хватает. Это самая частая причина «мод рисует только шлем»: в паке есть только он.

## Ассеты: где что лежит

GeckoLib 5 ищет файлы не там, где писалось в старых гайдах. Единственные рабочие пути:

| Что | Файл | Как ссылаться в конфиге |
|---|---|---|
| Геометрия | `assets/<ns>/geckolib/models/<имя>.geo.json` | `"mypack:<имя>"` |
| Анимации | `assets/<ns>/geckolib/animations/<имя>.animation.json` | `"mypack:<имя>"` |
| Текстура | `assets/<имя>/textures/.../файл.png` | полный путь `"mypack:textures/.../файл.png"` |

Текстура — исключение: GeckoLib отдаёт её прямо в рендер, поэтому нужен полный ресурсный путь, а не
короткое имя.

Имя модели — просто `неймспейс:имя`, без папок и расширений. Привычная запись вида
`mypack:geo/iron_set.geo.json` тоже понимается (мод приводит её к тому же виду), но канонична
короткая.

## Кости и координаты

Мод рисует **не всю модель**, а по одной кости на часть тела. Модели без нужной кости мод сам
предупредит в логе, один раз на модель и часть:

```
minecraft:golden_leggings: geo 'mypack:helmet' has no 'armorLeftLeg' bone, the segment will not be drawn
```

Кость по имени ищется по всей модели, включая вложенные, поэтому геометрию можно держать под одной
корневой костью. Но имя кости должно совпадать точно — переименованная (`head` вместо `armorHead`)
считается отсутствующей.

| Часть | Предмет (пример) | Кости, которые рисуются |
|---|---|---|
| Шлем | `minecraft:iron_helmet` | `armorHead` |
| Нагрудник | `minecraft:iron_chestplate` | `armorBody`, `armorLeftArm`, `armorRightArm` |
| Поножи | `minecraft:iron_leggings` | `armorLeftLeg`, `armorRightLeg` |
| Ботинки | `minecraft:iron_boots` | `armorLeftBoot`, `armorRightBoot` |

Руки принадлежат нагруднику — так же, как в ванильной модели брони.

### Пивот кости

Кость вращается **вокруг своей точки вращения (`pivot`)**, а не вокруг центра кубов. Для сегмента
брони эта точка — сустав: рука вращается в плече, нога в бедре, как в ванильной модели. Blockbench
оставляет пивот там, где его последний раз тянули, поэтому у костей брони его надо проверить руками:

| Кость | Пивот |
|---|---|
| `armorHead`, `armorBody` | `[0, 24, 0]` |
| `armorRightArm` / `armorLeftArm` | `[-5, 22, 0]` / `[5, 22, 0]` — плечо |
| `armorRightLeg` / `armorLeftLeg` | `[-2, 12, 0]` / `[2, 12, 0]` — бедро |
| `armorRightBoot` / `armorLeftBoot` | как у ноги: `[-2, 12, 0]` / `[2, 12, 0]` |

Пивот, стоящий на самой геометрии, — самая частая причина жалобы «перчатки/наплечники приклеены к
телу»: такая кость вращается вокруг себя и остаётся на месте, пока рука уходит вперёд. Так же ведут
себя ноги и ботинки. Кости ботинок ведёт та же кость ноги, поэтому их пивот — тот же бедренный.

Модель собирается в **человеческой системе Bedrock**: 16 единиц = 1 блок, ступни на нуле, тело
12–24, голова 24–32. Ось X зеркальна ванильной. Если геометрия из Blockbench стоит на нуле, шлем
окажется у ног: поднимай кубы на +24 по Y или пересобирай модель в этой системе.

Один файл геометрии может нести весь сет — части просто берут из него свои кости. Именно так
устроен `iron_set.geo.json` в примере.

## Размещение модели: `display`

Если модель делалась не под кости брони, а как предмет (например, шапка из Blockbench), её нужно
подвинуть. Числа — те же, что Blockbench пишет в *Display → Head* предметной модели:

```json
"display": {"translate": [1.6, -2.75, 0], "rotate": [0, 0, 0], "scale": 1.6}
```

- `translate` — в единицах модели (16 = один блок, +Y вверх);
- `rotate` — в градусах;
- `scale` — одно число или `[x, y, z]`.

Смещение применяется внутри кости брони, поэтому шлем при повороте головы едет вместе с головой, а
не остаётся приколотым к телу. Без `display` модель берётся ровно такой, как нарисована.

## Прозрачность: `translucent`

Обычная броня рисуется отсечением (cutout): пиксель либо есть, либо его нет, полутона не
смешиваются. Полупрозрачный арт — стекло, визор, призрачная броня — выйдет сплошным.

`"translucent": true` включает обычное альфа-смешивание. Стоит это корректной сортировки
отрисовки, поэтому включён по умолчанию только у тех вещей, где он запрошен.

## Свечение: `glow`

Светящиеся детали делаются **маской свечения** — отдельной картинкой с той же разметкой UV, что у
основной текстуры. Горят только её непрозрачные пиксели, и горят в полную яркость, независимо от
времени суток и освещения.

```json
"glow": true
```

`true` (или `"glow"`) включает проход и берёт маску рядом с текстурой, добавив `_glowmask` перед
`.png`: `textures/armor/set.png` → `textures/armor/set_glowmask.png`.

```json
"glow": "radiant"
```

То же свечение, только «раскалённое»: яркость базовой текстуры умножается примерно в 2.5 раза, и
пиксели уходят за собственный цвет арта — деталь читается как источник света, а не как
незатенённая. Так рисуется `Mode.RADIANT` в Armor Model API: пак, написанный под него, выглядит
здесь так же.

```json
"glow": {"mask": "mypack:textures/armor/runes.png", "mode": "radiant"}
```

Явная маска — если файл лежит в другом месте или маски нужны разные на части сета. Ключ `mode`
задаёт вид свечения, без него проход обычный (`"glow"`).

Выключить свечение — `"glow": false` или просто убрать ключ.

Маска — это обычный PNG той же раскладки, что базовая текстура: горит то, что нарисовано в ней
непрозрачным. Для глаз, клинка или рунных линий достаточно нарисовать их белым по прозрачному
фону. Если файла маски нет, светится вся вещь целиком — мод предупредит об этом в логе
(`glow mask '...' does not exist, the whole piece will glow`).


## Перезагрузка и отладка

Паки перечитываются по **F3+T** (зажать F3, нажать T) — перезапуск игры не нужен: мод заново
просматривает паки и применяет новые настройки сам.

Первая строка говорит, что мод жив; вторая — сколько записей нашлось в паках; третья — сколько
предметов реально получили модели (лишние записи отбрасываются с причиной — см. ниже). Для
полного лога запусти игру с `-Dgeoarmor.debug=true`: добавятся строки вида

```
minecraft:iron_helmet -> mypack:iron_set / mypack:textures/armor/iron_set.png (slot HEAD, animation off, translucent false, glow GLOW mypack:textures/armor/iron_set_glowmask.png)
geo armor pass: slot=HEAD minecraft:iron_helmet
render mode for minecraft:iron_helmet: cutout + glow GLOW @ THIRD_PERSON_BACK
minecraft:iron_chestplate: geo 'mypack:iron_set' segment bone pivots: armorBody=[0.0, 24.0, 0.0] armorLeftArm=[-5.0, 22.0, 0.0] armorRightArm=[5.0, 22.0, 0.0]
```

Первая строка — что пак попросил, вторая — что реально рисуется (по строке на кадр и на часть),
третья — каким типом и в каком лице, четвёртая — пивоты костей частей, один раз на модель. Сверь
последнюю строку с таблицей «Пивот кости»: именно там видно, что рука или нога вращается вокруг
собственной геометрии, а не вокруг сустава. Ось X в этой строке — уже зеркальная (GeckoLib читает
модель зеркально), то есть числа по X идут со знаком, обратным `.geo.json`: `-5` в файле — это `5.0`
в логе.

## Частые ошибки

| Симптом | Причина |
|---|---|
| Рисуется ванильная броня | Нет записи для **этого** предмета. Ключ — id предмета, а не слот и не семейство |
| В логе нет строки `Loaded N armor setting(s)` | Нет ключа `armor` или файл лежит не в `assets/<ns>/config/armor/` |
| Часть модели не отрисовалась | В модели нет кости этой части (`armorHead` и т.д.); в логе `geo '...' has no 'armorLeftLeg' bone, the segment will not be drawn` |
| Текстура в фиолетово-чёрную клетку | Неверный `texture` или файла нет; в логе `texture '...' does not exist, will render missing-texture` |
| `geo '...' has no ...geo.json, entry skipped` | Файла геометрии нет по этому имени; лог называет ожидаемый путь |
| Полупрозрачный арт сплошной | Нужен `"translucent": true` |
| Свечение не горит | Нет ключа `glow`; если маски нет — в логе `glow mask '...' does not exist`, и светится вся вещь целиком |
| Шлем у ног, модель в масштабе 1/16 | Геометрия не в человеческой системе — подними кубы на +24 по Y |
| Рука или нога «приклеена» к телу и не едет за ней | Пивот кости сегмента стоит на самой геометрии, а не в суставе — см. «Пивот кости» (`[-5, 22, 0]`/`[5, 22, 0]`, `[-2, 12, 0]`/`[2, 12, 0]`) |
| Модель не видно в первом лице | Так и должно быть: своя броня в первом лице не рисуется |
| Модель не видна в превью инвентаря | Превью показывает ванильную модель, GeckoLib-броня рисуется только на живой сущности |

Сообщения уровня `warn` в логе — это почти всегда ошибка автора пака, а не мода: мод перечисляет,
что именно он не смог найти, и продолжает работу с тем, что осталось.

## Ограничения

- **Только надеваемая броня.** Предмет, который игра не считает бронёй, получить эту модель не
  может — в лог уходит `item is not equippable armor, entry skipped`.
- **Только видимая часть.** В первом лице своя броня не рисуется (как и ванильная), а
  превью-модель в инвентаре показывает ванильные слои.
- **Один слой.** Ванильная броня под 3D-моделью не остаётся: слой подменяется целиком, иначе
  геометрия торчала бы сквозь нарисованное.
- **Анимация — на покое.** Пак задаёт `idle`-клип; как сработает остальное, решает GeckoLib-модель.

## Сборка из исходников

```bash
./gradlew build        # jar в build/libs/geoarmor-1.0.0.jar
./gradlew test         # тесты парсера пака, без запуска игры
```

26.2 выходит без обфускации, поэтому маппингов в проекте нет, а имена — моджановские. Loom нужен
**Gradle JVM 25+**; `options.release = 25` — это про код, а не про JVM сборки.

Запуск дев-клиента (GeckoLib и Fabric API подтягиваются сами):

```bash
./gradlew runClient --args="--quickPlaySingleplayer TEST"
```

Игра становится в мир `run/saves/TEST`, где игрок носит полный железный сет; включён
`-Dgeoarmor.debug=true`, поэтому в логе сразу видно и разбор пака, и что рисуется.
